# 스터디룸

여러 과목을 등록하고 풀 수 있는 브라우저 모의고사입니다. 해킹실무 1~7주차 221문항과 네트워크보안응용 중간고사 Lecture 1~4의 184문항을 제공합니다. 별도 서버·설치·API 키·빌드 과정 없이 HTML, CSS, JavaScript로 동작합니다. 외부 폰트나 CDN도 사용하지 않습니다.

## 지금 실행하기

`index.html`을 Chrome 또는 Edge로 열면 바로 풀 수 있습니다. 모든 파일을 같은 폴더 구조로 유지하세요. 로컬 파일 주소에서도 동작하도록 `fetch`와 JavaScript 모듈을 사용하지 않았습니다.

## GitHub에서 접속하기

GitHub 저장소의 코드 화면 자체에서 시험이 실행되는 것은 아닙니다. **GitHub Pages**를 한 번 켜면 별도 서버 운영 없이 사이트 주소로 접속할 수 있습니다.

1. GitHub 저장소에 `index.html`, `assets/` 폴더 전체, `data/` 폴더 전체, `.nojekyll`을 폴더 구조 그대로 업로드합니다. 원본 PDF는 업로드할 필요가 없습니다.
2. 저장소 **Settings → Pages → Build and deployment**에서 **Source: Deploy from a branch**를 선택합니다.
3. 파일을 업로드한 브랜치(예: `main`)와 **/ (root)**를 선택하고 **Save**합니다.
4. Pages 설정에 표시되는 주소에 접속합니다. 일반적인 프로젝트 주소 형태는 `https://사용자명.github.io/저장소명/`입니다.
5. 이후 해당 브랜치에 파일 변경을 업로드하면 사이트에도 반영됩니다.

운영 사이트: https://dtd2428.github.io/study/ · 저장소: https://github.com/dtd2428/study

이 `study` 폴더가 GitHub Desktop과 연결된 실제 작업 저장소입니다. 상위 폴더의 `archive/initial-site/`는 보관용이며, 이후 수정은 이 저장소에서 진행하세요.

공식 안내: [GitHub Pages 게시 소스 설정](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

## 제공 기능

- 시작 화면의 **문제풀기**를 누르면 전체 과목 범위에서 중복 없이 **무작위 30문항**을 새로 뽑습니다. 누를 때마다 문제 구성·순서와 객관식 보기가 다시 섞입니다. 미완료 시험이 있으면 새 시험으로 교체합니다. 문제가 30개 미만인 새 과목은 등록된 전체 문항을 사용합니다.
- 주차·유형 등을 따로 고르고 싶으면 **주차·유형별 맞춤 학습 설정**을 펼쳐 시작합니다.
- 해킹실무 문제 **221문항**: 4지선다 53, 단답형 76, 빈칸 16, 서술형 76.
- 네트워크보안응용 중간고사 **184문항**: 4지선다 58, 단답형 67, 빈칸 43, 서술형 16. 제공된 34쪽 통합 PDF의 자가 점검 60문항, 개념 응용 40문항, 쉬운 기초 확인 84문항이며, 각 문제에 통합 PDF 쪽수를 표시했습니다. [범위와 채점 안내](data/subjects/network-security-midterm/README.md).
- 네트워크보안응용의 **주차·유형별 맞춤 학습 설정 → 문제 유형 → 기본개념문제**를 체크하면 기초 84문항만 출제합니다. 주차·답안 유형 선택도 함께 적용하며, 위쪽 **문제풀기** 버튼에서도 기본 개념만 무작위 최대 30문항 출제합니다. 전체 84문항은 출제 문항 수를 **선택 범위 전체**로 고르세요.
- 과목, 주차, 유형, 문항 수, 제한 시간 선택.
- 시험을 새로 시작할 때 문제 순서와 객관식 보기 순서를 각각 Fisher–Yates 방식으로 섞습니다. 우연히 이전과 같은 순서가 나올 수 있습니다.
- 시험 도중 이동하거나 새로고침해도 같은 보기 순서·답안·남은 시간을 복원합니다.
- 연습 모드: 답안을 입력한 후 문제별 정답과 해설 확인. 확인 후 **다시 풀기 ↻**를 누르면 현재 문항의 답안·확인 상태·직접 평가만 초기화하고 해설을 숨겨 바로 재도전합니다. 다른 문항의 답안, 표시, 순서와 제한 시간은 유지합니다. 제출할 때는 마지막 답안으로 채점합니다.
- 객관식에서 오답을 선택하면 **선택한 답은 왜 틀렸을까요?**에 그 보기의 개념과 틀린 이유를 표시합니다. 기본 과목 객관식 111문항의 오답 보기 333개에 해설을 제공합니다. 연습은 정답 확인 후, 모의고사는 제출 후 표시하며 학습 기록에서도 확인합니다. 이전 저장 문제도 문제·보기·정답이 모두 같은 경우 새 해설을 보완합니다.
- 모의고사 모드: 제출 전까지 해설 숨김. 미응답도 포함해 전체 채점.
- 단답형: 허용 답안과 비교합니다. 유니코드 NFKC, 앞뒤 공백, 연속 공백을 정규화하고 **대소문자는 구분**합니다. 의미 기반 AI 채점은 아닙니다.
- O/X 문항은 **O · 맞다 / X · 틀리다** 버튼으로 선택합니다. 선택은 자동 저장되며 정답 확인 후 잠깁니다. 기존에 입력한 답안도 복원합니다.
- UID 빈칸: 한 문제의 모든 칸이 맞아야 정답으로 처리합니다.
- 빈칸형은 채점 후 칸마다 정답·오답을 표시하고, 해설에 각 칸의 입력값과 틀린 칸의 정답을 보여줍니다. 내부 공백을 허용하지 않는 답안은 입력 전 **띄어쓰기 금지**를 표시합니다. 단답형도 모든 허용 답안에 내부 공백이 없으면 같은 안내를 표시합니다. 문항 점수는 기존처럼 모든 칸이 맞아야 정답입니다.
- 서술형: 모범답안·평가 항목을 보고 직접 `충족 · 정답` 또는 `미흡 · 복습`을 선택합니다. 미평가 문항이 있으면 임시 점수로 표시합니다.
- 문항별 동일 배점, 총 100점 환산, 정수 반올림. 서술형 직접 평가 결과도 점수에 포함됩니다.
- 표시해 둔 문제, 오답·미평가 문제 복습, 전체 다시 풀기.
- 풀이 화면의 **나만 제외**로 현재 문항을 해당 브라우저의 문제은행에서 즉시 제외합니다. 현재 시험에서도 제외되어 총 문항 수가 줄고, 다음 출제·기록에서 다시 풀기에도 나오지 않습니다. 마지막 삭제는 상단 **삭제 취소**로 복원할 수 있으며 새로고침 후에도 취소할 수 있습니다. 마지막 문항을 삭제하면 시험을 종료하고 홈으로 돌아갑니다.
- **나만 제외**는 해당 브라우저에만 적용합니다. 상단 안내 오른쪽 **X**는 삭제를 유지한 채 안내만 닫으며, 새로고침 후에도 닫힌 상태가 유지됩니다.
- 빨간 **문제 삭제 ↗**는 GitHub 원본 삭제 요청을 엽니다. GitHub에서 Issue를 등록해야 처리됩니다. 소유자 요청은 자동 처리하고, 친구의 요청은 소유자가 승인 라벨을 붙이면 반영합니다. 원본 문제 파일을 수정하고 Pages를 재배포하므로 전체 사이트 문항 수가 줄어듭니다. [전체 사이트 삭제 안내](docs/shared-deletion.md)를 참고하세요.
- 로컬 제외만 한 경우  이미 완료한 기록·해설과 친구의 문제은행은 유지됩니다. 다른 방문자에게도 반영하려면 관리 화면에서 배포용 `overrides.js`를 받아 `data/overrides.js`로 업로드하세요.
- 최근 50회 답안·점수·해설 기록. 주차별 정답 수.
- 새 과목 생성, 네 가지 유형의 문제 직접 추가·삭제, JSON 가져오기·내보내기.
- 휴대전화와 PC에 맞춘 화면, 키보드 탐색, Alt+좌우 방향키로 문제 이동, Alt+Enter로 연습 모드 정답·해설 확인.

제한 시간은 탭을 닫거나 학습 홈으로 나가도 경과합니다. 시간이 지나면 실행 중인 페이지에서 자동 제출하며, 닫혀 있었다면 다음 실행 때 제출합니다. 브라우저가 백그라운드 타이머를 지연시키면 화면 갱신이 늦어질 수 있으나 마감 시각은 유지됩니다.

## 과목을 계속 추가하기

파일로 관리할 때는 `data/subjects/과목-id/questions.js`에 작성하고 `data/subjects.js`에 등록합니다. 복사용 템플릿과 전체 절차는 [과목 추가 안내](docs/adding-subjects.md)에 있습니다.

### 웹 화면에서 작성

1. **과목 · 문제 관리 → 새 과목 만들기**에서 이름과 주차 수를 입력합니다.
2. 해당 과목의 **문제 추가**에서 유형, 주차, 문제, 정답, 해설을 입력합니다.
3. 다른 브라우저에서도 이어서 관리하려면 **모든 과목 JSON 내보내기**로 백업하고 가져옵니다.
4. 사이트의 모든 방문자에게 새 문제를 제공하려면 **GitHub 배포용 overrides.js 받기**를 눌러 내려받고 저장소의 **`data/overrides.js`를 그 파일로 교체**해 업로드합니다. 공통 HTML·JavaScript를 바꿀 필요는 없습니다. 과목별 파일로 관리하는 방법과 데이터 적용 순서는 [과목 추가 안내](docs/adding-subjects.md)를 참고하세요.

브라우저에서 편집한 문제은행은 그 브라우저의 수정본으로 보관됩니다. 새 배포의 기본 문제은행보다 수정본이 우선합니다. 새 기본본으로 덮어쓰려면 관리 화면에서 새 JSON을 가져와 해당 ID의 과목 교체를 승인하세요. 기존 기록에는 시험 당시 문제와 답안이 보존됩니다.

### JSON 가져오기

관리 화면의 **새 과목 예시 파일 받기**로 시작하세요. 한 과목 객체 또는 여러 과목 객체의 배열을 받습니다. 최대 10MB, 과목당 3,000문항, 1~30주차를 지원합니다. 잘못된 파일은 전체 검증 후 거절하므로 일부만 가져오지 않습니다.

```json
[
  {
    "id": "my-subject",
    "title": "새 과목",
    "description": "과목 소개",
    "source": "교재 또는 강의 이름",
    "weeks": ["첫 번째 단원", "두 번째 단원"],
    "questions": [
      {
        "id": "q-001",
        "week": 1,
        "type": "choice",
        "prompt": "문제 내용",
        "options": [
          { "id": "a", "text": "정답 내용" },
          { "id": "b", "text": "다른 보기 1" },
          { "id": "c", "text": "다른 보기 2" },
          { "id": "d", "text": "다른 보기 3" }
        ],
        "answer": "a",
        "explanation": "정답이 되는 이유와 다른 개념의 차이",
        "source": "교재 12쪽"
      }
    ]
  }
]
```

모든 문제는 `id`, `week`, `type`, `prompt`, `explanation`을 가집니다. `source`는 선택입니다. 문제 ID는 과목 안에서 유일해야 합니다.

| 유형 | 추가 필드 | 채점 |
| --- | --- | --- |
| `choice` | 서로 다른 `options` 4개, 정답 보기 ID인 `answer` | 번호 대신 ID로 비교 |
| `short` | `answers: ["허용 답안", "다른 표기"]` | 배열 중 하나와 일치 |
| `blanks` | `fields: ["라벨1", "라벨2"]`, `answers: ["정답1", "정답2"]` | 순서대로 모든 칸 일치 |
| `essay` | `model`에 모범답안, `rubric: ["평가 항목"]` | 직접 평가 |

서술형은 `model`과 `explanation`에 동일한 모범답안을 넣습니다. 오타를 방지하려면 웹의 문제 추가 폼을 사용하세요. 파일의 문자열은 화면에 텍스트로 표시하며 HTML로 실행하지 않습니다.

빈칸형은 선택 필드 `answerAliases: [["첫 칸 추가 답안"], ["둘째 칸 추가 답안"]]`로 칸별 복수정답을 지원합니다. 바깥 배열은 빈칸 수와 같아야 하며, 각 칸은 기본 `answers` 값 또는 해당 칸의 추가 답안 중 하나와 일치하면 정답입니다. 빈 배열은 추가 답안이 없는 칸입니다. 띄어 쓴 허용 답안이 있는 칸에는 띄어쓰기 금지 안내를 표시하지 않습니다. JSON 내보내기·가져오기로 보존됩니다.

객관식 보기에는 선택 필드 `explanation`을 작성할 수 있습니다. 예: `{ "id": "a", "text": "네트워크 계층", "explanation": "네트워크 계층은 OSI 3계층입니다." }`. 웹의 문제 추가 화면에서도 각 보기 아래 **보기 설명 (선택)**을 입력할 수 있습니다. 선택한 오답의 해설만 보여주며 공통 `explanation`은 정답의 이유를 설명합니다. 보기별 해설이 없는 직접 추가 문항은 기존 공통 해설을 표시합니다.

## 친구 제공 문제 추가

친구가 제공한 해킹실무 문제풀이 HTML 소스의 데이터에서 142문항을 추가했습니다. 주차별 135문항, 해킹 5단계 서술형 6문항, 실전 예상에서만 등장하는 객관식 1문항입니다. 실전 예상의 나머지 13문항은 주차별·서술형 문항과 같아 중복 등록하지 않았습니다. 기존 97문항의 ID와 내용은 유지했습니다. 기존 문제와 주제가 겹치는 친구 문항은 표현·상황별 복습을 위해 함께 제공합니다.

명령어·용어는 단답형, UID 사례는 호출 전후 네 값을 입력하는 빈칸형, 문장 설명·복수 예시 답안은 서술형 직접 평가로 옮겼습니다. 원문의 실습 화면·코드는 문제에, 참고 사항은 해설에 포함했습니다. 출처에 `친구 제공 문제집`과 원문 주차·쪽수를 표시하며 기존 통합 PDF 쪽수와 구분합니다. 첨부 HTML의 실행 코드는 가져오지 않았습니다.

## 자료와 저장 방식

문제와 해설은 제공된 **해킹실무 1~7주차 통합정리 빈칸학습 PDF(35쪽)**의 내용을 바탕으로 작성했습니다. 해설의 쪽수는 PDF 페이지 기준입니다. 실습 환경에 따른 결과는 문제와 해설에 해당 전제를 남겼으며, 과거 도구·암호화 관련 표현을 최신 운영 지침으로 바꾸어 출제하지 않았습니다.

이 사이트는 준비된 문제은행을 출제하며 **새 PDF를 자동으로 읽거나 AI로 문제를 생성하지 않습니다.** 새 과목은 수동 작성 또는 다른 곳에서 준비한 JSON 가져오기로 추가합니다.

기록과 직접 추가한 문제는 `localStorage`의 `studyroom-v1`에 저장하고, 로컬 제외 목록과 안내 닫기 상태는 `studyroom-deletions-v1`에 별도로 저장합니다. 로그인이나 기기 간 동기화는 없습니다. 브라우저 데이터 삭제 시 없어질 수 있으므로 추가한 과목은 JSON으로 백업하세요. 저장 공간을 사용할 수 없으면 알림을 표시하며 해당 탭에서는 계속 풀 수 있습니다. 파일 주소와 GitHub Pages 주소의 저장 공간은 별개입니다.

정답도 JavaScript에 포함됩니다. 개인 학습용 모의고사에 맞는 방식이며, 정답 은닉이나 감독이 필요한 공식 시험 시스템은 아닙니다.

사용자는 Node나 Python을 설치할 필요가 없습니다. 개발 검증은 Node와 Playwright가 있는 환경에서 `node tests/smoke.cjs`로 실행합니다. 기본 브라우저는 설치된 Chrome이며 `BROWSER_CHANNEL=msedge` 등으로 변경할 수 있습니다. 테스트 화면과 중간 파일은 Git에서 제외하는 `tmp/`에 생성됩니다.

과목 파일 로딩과 기존 저장 기록 호환성 검증은 `node tests/subjects.cjs`로 실행합니다.

네트워크보안응용 184문항의 로딩·출제·유형별 채점·Lecture별 필터 검증은 `node tests/network-security.cjs`로 실행합니다.

빈칸별 정오답·띄어쓰기 안내·기록 복원·모의고사 해설 표시 검증은 `node tests/blanks-feedback.cjs`로 실행합니다.

연습모드의 현재 문항 다시 풀기·다른 답안 보존·전체 답안 유형 검증은 `node tests/retry-current.cjs`로 실행합니다.

보기별 오답 해설 333개·섞인 보기 ID·이전 저장본·모의고사·직접 작성 검증은 `node tests/choice-feedback.cjs`로 실행합니다.

풀이 중 삭제·취소·새로고침·기록 보존 검증은 `node tests/deletion.cjs`로 실행합니다.

원본 삭제 자동화 검증: `node --test tests/source-deletion.cjs`. 안내 X·삭제 목록 저장 검증: `node tests/deletion-controls.cjs`.

SUID 다섯 사례의 시각적 조건 표시·UID 입력 채점 검증은 `node tests/uid-practice.cjs`로 실행합니다.

해킹실무의 **주차·유형별 맞춤 학습 설정 → SetUID만 학습**을 체크하면 전용 UID 계산 5문항만 출제합니다. 주차·유형 선택과 함께 적용하며, 위의 문제풀기 버튼에도 체크 상태를 반영합니다. 체크를 해제하면 전체 문제은행을 이용합니다.
